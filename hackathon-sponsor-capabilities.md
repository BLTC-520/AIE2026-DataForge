## Platform Notes

### OpenAI / Codex

OpenAI is the strongest default model layer for this event because GPT-5.5 and Codex are explicit tracks. Use GPT-5.5 for reasoning, typed JSON, tool planning, and report generation. Use Codex where the project includes real repository work. Use GPT Realtime 2 or Realtime Translate only if voice or translation is part of the core loop. Use GPT Image 2 only if image generation/editing is central to user value.

Good uses:

- Convert ambiguous user input into a typed plan, tasks, tests, and acceptance criteria.
- Use tool calling or structured output to drive a real workflow instead of returning only text.
- Add Codex to build, fix, or review code in a visible way.
- Generate or edit images when the image output is essential to the product.

Sources:

- https://platform.openai.com/docs/guides/text
- https://platform.openai.com/docs/guides/images-vision
- https://developers.openai.com/codex

### Gemini

Gemini has explicit gen media and voice agent tracks. It is strongest when the demo uses multimodal reasoning, voice/live interaction, or generated media as a real product capability rather than decoration.

Good uses:

- Live voice agent with interruption, streaming, and tool calls.
- Video, music, or image media generation for a product workflow.
- Multimodal reasoning across text, image, audio, or video.

Sources:

- https://ai.google.dev/gemini-api/docs
- https://ai.google.dev/gemini-api/docs/live

### Adaption Labs

The slide deck confirms a dedicated Adaption Labs prize track and participant credits. For DataForge, keep the product boundary honest: Adaption Labs should be positioned as an adaptive data or manifest-level quality loop where available, not as the component that inspects image pixels unless the sponsor explicitly confirms that capability on site.

Good uses:

- A workflow that visibly improves after user feedback.
- Dataset, prompt, or workflow adaptation where before/after quality can be shown.
- A loop that separates measured metrics from model interpretation.

Project fit for DataForge:

- Strong fit if used for manifest-level dataset lifecycle, evaluation, adaptation, or quality snapshots.
- Do not claim Adaption Labs visually detects cats, dogs, duplicates, or mislabeled images unless the live API supports image-pixel analysis.

### Convex

Convex is the best sponsor fit for making a hackathon app feel alive. It gives a TypeScript backend, realtime sync, document database, queries, mutations, actions for external APIs, auth integrations, file storage, scheduled jobs, and search options.

Good uses:

- Realtime pipeline stage updates.
- Live event logs and judge-visible progress.
- Collaborative review state.
- File metadata and export records without separate backend infrastructure.

Source:

- https://docs.convex.dev/home

### Cursor SDK

Cursor SDK is a high-leverage track when the project includes a coding agent. The best demos show the agent doing concrete engineering work, not just describing code.

Good uses:

- Turn a bug report or issue into a branch and PR.
- Repair CI/test failures.
- Let users approve generated patches.
- Show streamed coding-agent progress in the product.

Sources:

- https://cursor.com/blog/typescript-sdk
- https://cursor.com/changelog

### Fal

Fal is strongest for fast generative media and model workflows. It supports many optimized model endpoints across image, video, audio, music, speech, 3D, streaming, and serverless GPU use cases.

Good uses:

- Generate visual/audio/video assets during the demo.
- Compare multiple media models for the same task.
- Add approved synthetic media only when tied to a clear user need.

DataForge caution:

- If used, generated animal images must be labeled synthetic and tied to a measured class or scenario gap.

Source:

- https://fal.ai/docs

### Exa

Exa is now an explicit track and participant-credit sponsor. It is a search API built for AI agents, with fast search, deep search, highlights, structured outputs, and category-specific retrieval for companies, people, research papers, news, personal sites, and financial reports.

Good uses:

- Ground an agent with current web evidence.
- Build research, sourcing, market-map, or enrichment workflows.
- Return structured research output rather than raw links.
- Use highlights to keep retrieval token-efficient.

Sources:

- https://docs.exa.ai/
- https://exa.ai/docs/llms.txt

### Smithery

Smithery is an MCP platform and connector marketplace. It is useful when the project needs many external tools quickly and the team does not want to build every integration from scratch.

Good uses:

- Connect agents to Gmail, GitHub, Notion, Slack, Google Sheets, search, browser tools, or databases.
- Use MCP connectors with managed auth and sessions.
- Publish an MCP server if the project exposes reusable tools.

Source:

- https://smithery.ai

### Vercel

Vercel is the safest web deployment path for a polished hackathon demo. It is strong for Next.js, serverless functions, AI SDK, AI Gateway, preview deployments, and observability.

Good uses:

- Deploy a live link judges can open immediately.
- Stream model output through a Next.js app.
- Use preview deployments for review.
- Add AI Gateway if model routing, fallback, or usage visibility matters.

Source:

- https://vercel.com/docs

### Daytona

Daytona is useful for safe execution. It provides isolated sandboxes with filesystem access, process execution, git operations, PTY, logs, snapshots, previews, and SDKs.

Good uses:

- Run generated code safely.
- Let agents execute tests in an isolated environment.
- Provide reproducible workspaces per task.
- Show terminal/test output as proof of work.

Source:

- https://www.daytona.io/docs/

### Hyperspell

Hyperspell is a memory/context sponsor. Use it when agent value depends on remembering user, company, workspace, or project context over time.

Good uses:

- Agent that knows workspace history, documents, emails, or messages.
- Meeting prep, sales prep, recruiting, support, or operations agents.
- Context retrieval without building a full ingestion pipeline.

Sources:

- https://hyperspell.com
- https://docs.hyperspell.com

### Manus

Manus provides general AI work-agent capabilities for creating slides, websites, desktop apps, design assets, browser operation, wide research, mail, Slack, and API workflows.

Good uses:

- Generate pitch assets or slide drafts quickly.
- Automate research and browser tasks.
- Build support artifacts around the main demo.
- Prototype UI, websites, or app flows when speed matters.

Sources:

- https://manus.im/
- https://open.manus.ai/docs

### Mobbin

Mobbin is a design inspiration and UI pattern library. The slide deck gives participants 3 months of Mobbin Pro, making it useful for improving polish under time pressure.

Good uses:

- Reference real-world web and mobile app screens.
- Improve onboarding, dashboards, settings, export flows, and empty states.
- Find proven UX copy and interaction patterns.
- Copy or adapt patterns into Figma before implementation.

Source:

- https://mobbin.com/

### ElevenLabs

ElevenLabs is best for voice polish and audio-first UX. It provides text to speech, speech to text, voice cloning, dialogue, sound effects, dubbing, music, and conversational agents.

Good uses:

- Voice UI over a serious backend workflow.
- Human-sounding demo narration.
- Multilingual dubbing or translation experiences.
- Sound effects and music for media products.

Source:

- https://elevenlabs.io/docs/overview

### Cloudflare

Cloudflare appears in the overall winner credit package. It can serve as production infrastructure through Workers, Durable Objects, AI Gateway, Vectorize, R2, D1, KV, Workflows, and Agents SDK.

Good uses:

- Stateful agents on Durable Objects.
- Model routing, caching, and usage observability through AI Gateway.
- Edge APIs and durable workflows.
- RAG storage with Vectorize plus R2/KV/D1.

Sources:

- https://developers.cloudflare.com/ai/
- https://developers.cloudflare.com/agents/
- https://developers.cloudflare.com/workers/

## DataForge Sponsor Strategy

DataForge should not sponsor-stuff. The strongest pitch is still a closed-loop image dataset repair cockpit.

Best target set:

- Adaption Labs: manifest-level adaptive quality/evaluation loop where available.
- GPT-5.5: structured quality report, repair recommendations, and label/balance explanation.
- Convex: realtime pipeline, events, review decisions, and dashboard state.
- Vercel: live deployed web app.
- Fal or GPT Image 2 only as optional stretch for clearly marked synthetic additions after measured gaps.

Possible extra angles:

- Exa can gather external label taxonomy or dataset best-practice evidence, but it is not core to the current DataForge loop.
- Mobbin can improve dashboard polish, but it should not be listed as a sponsor track unless the UI improvement is visible.
- ElevenLabs/Gemini voice should only be added if the demo becomes voice-driven.

Avoid:

- Claiming Adaption Labs inspected image pixels without confirmed support.
- Claiming model accuracy improvement without training and evaluating a model.
- Adding voice, code agents, or web research if they distract from the dataset repair story.
- Listing sponsor tracks where the tool is not meaningfully part of the demo.

## Judging Guidance From Slides

Slide 12 says to make the project easy to judge: pick only relevant tracks, explain the project in one line, show a working path, and keep the demo tight.

Slide 13 says strong demos prove four things:

- It works.
- It matters.
- It uses AI deeply.
- It feels finished enough.

For DataForge, that means the demo should open with the broken dataset, show the repair loop, let the user approve concrete fixes, prove before/after quality deltas, and avoid adding unrelated sponsor features.
